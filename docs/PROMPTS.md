# 提示词全景

> 一次 AI 优化实际下发什么、每一段由谁负责、改哪里会触发哪条机检。
> 对应代码：`server.js` 的 `aiPrompts()` / `aiRules()` / `aiReview()`。
> 最近整理：2026-11-15 第二十八批。

## 拼装顺序

```
system = 内置骨架（固定 760 字） + 【本任务要求】（任务 config.notifyPrompt，可空）
user   = 任务名 / 原始标题 / 原始内容 / 【接口原始数据】 / 【默认优化要求】 / 【交付前自检】
```

优先级：**任务要求 > 体例 > 默认要求**；**事实纪律、禁止的写法 > 任务要求**（底线，任务里写什么都压不动）。

## 1 内置骨架（760 字，随代码走，不可在页面上改）

| 段落 | 管什么 | 下游机检 |
| --- | --- | --- |
| 角色与输出契约 | 只输出 `{"title","body"}`，不解释、不带围栏 | 解析失败即重试 |
| 材料类型判定 | 结构化数据按字段取；长文本提炼 2~4 点、禁止整段照搬 | — |
| 事实纪律 | 数字/时间/名称必须逐字出现在原始数据；带原单位；多口径（当前价/预计价）不合并；缺项不凑「暂无」 | `fact-number` |
| 禁止的写法 | 空话套话、字段名入正文、自称 | `no-filler` |
| 体例 | 未指定时 ≤160 字；首行给结论；中文标点；不用 markdown、不留空行；数字与单位之间留空格 | `no-markdown` `no-blank-line` |

天气任务里「°C 紧贴数字」与骨架的「数字与单位留空格」冲突，由任务要求覆盖，并在 `aiPolish` 里做一次确定性归一（`tightUnits`）。

## 2 全局默认提示词（25 字）

```
精简易读，突出关键数字；必要时给一句具体建议。
```

- 作用域：**10 个没有自定义提示词的任务**全部用它；天气任务里它退为「补充要求」，与任务要求冲突时让位。
- 精简前 106 字，内容与骨架重复（不修改数据 / 纯文本 / 禁 markdown / 换行分层 / 生活建议），已删。
- 不能写成含「每行 N 字」「只输出 N 行」的句子——那会给所有任务凭空加一条机检。

## 3 天气任务提示词（1182 字）

任务 `task_2c265324420b`「天气预报·三甲集」，正本 `D:/Temp/2026-11-15-prompts/notifyPrompt-v6.txt`。

```
你是天气播报编辑。地点：甘肃临夏州广河县三甲集镇。今天 {{日期}}。

【输出】纯文本，禁 markdown、空行、标题、解释。只输出 3 行正文，行末不加句号。

【事实】天气内容只能逐字取自材料末尾的「【事实结论】」区：现象、温度、降水时段、预警名及级别。不推算、不换算、不补全，不用常识或历史播报补齐；逐日与逐小时原始行、状态串只供核对，不作取数来源。取不到的字段直接放弃——宁可缺一项，不可编一项。

【材料缺失】「【事实结论】」区为空，或今晚、明天两行都取不到字段时，只输出：
❄️ 数据不足
⛅ 本次不播报
💡 稍后重试

【取数｜每行只抄本行】今晚行只用「今晚」行，明天行只用「明天」行，互不借用。温度区间＝明天最低~明天最高，禁用「夜间最低」，禁止两行数据互换拼接。缺字段只写已有的，不留占位符。

【降水时段｜整段 > 单点 > 不写】
只抄本行「降水=」，原样拼在现象前：`今晚19-07时小雪`。24 小时制，`19-07时` 原样保留，末尾只一个「时」。
两行各写各的：不许因为一行写了就省另一行，也不许挪到另一行。
禁止「19时起，7时停」「19时到7时」「19时-7时」「19-07」等变体；时段不许提到行首。
写出的每个小时都必须落在结论区的降水区间内。

【三行｜〈〉是占位符，不得照抄】
❄️ 今晚〈时段〉〈现象〉，最低〈今晚最低〉
⛅ 明天〈时段〉〈现象〉，〈明天最低〉~〈明天最高〉
🧣 明早慢行
每行＝图标＋1 空格＋内容；信息点用「，」隔开；〈时段〉为空时连它一起省掉。
日期词不能省：每行必须写成「今晚…」「明天…」，不许直接从时段或现象开头。
温度区间只在末尾带一次 °C，写成「-1.5~6°C」。
建议行从「明早慢行 / 带伞 / 防滑 / 防晒 / 戴口罩 / 关窗」挑最贴的一句，只一句。

【预警】「预警名」非「无」→ 建议行改成「⚠️ 〈预警名〉；明早慢行」，整串逐字照抄，不翻译、不删级别、不改写、不自己加。orange / red 提到第 1 行，第 3 行恢复建议行；yellow / blue 留在第 3 行；⚠️ 全篇只出现一次。

【图标】按现象选，全篇不重复：
晴☀️ 晴间多云/多云⛅ 阴☁️ 雨🌧️ 雨夹雪/雪❄️ 雾🌫️ 雷⛈️ 沙尘🌪️ 风≥5🌬️ 夜间晴🌙
建议行：结冰🧣 雨☔ 污染😷 防晒🧢 干燥💧 其余💡
图标表是选图规则，里面的天气词不是本次事实。

【格式】只有 emoji 后留 1 个空格；°C 紧贴数字；行末不加句号。

【字数】正文 ≤58 字。超限删序：形容词 > 升降趋势 > 明天风力 > 今晚湿度 > 明天温度区间 > 今晚最低温。温度、湿度、风是酌情项：省掉不影响正确，写错就是编。
```

### 相对上一版（2105 字）删了什么

- 事实纪律 6 句 → 3 句：与骨架重复的「不改精度 / 不编 / 唯一来源」合并，保留天气特有的「结论区」「原始行只供核对」
- 阈值表（风 0-2 微风 / 3-4 稍大 / 紫外线 / 湿度）整段删除：当前输出根本不写这些字段，58 字也留不出位置
- 每行字段顺序、删序解释、建议行说明合并成一句
- 材料缺失的 3 行保留（属于硬性降级契约）

### 相对上一版补了什么

- 「日期词不能省」：精简后模型一度输出 `❄️ 19-07时小雪`，丢掉「今晚」
- 「温度区间只在末尾带一次 °C」：同一版里出现过 `-1.5°C~6°C` 双单位

## 5 机检规则的触发词（改提示词别删这些字）

| 规则 | 触发条件 | 硬/软 | 删了会怎样 |
| --- | --- | --- | --- |
| `line-count` | 出现「只输出 3 行」 | 硬 | 少写一行照发 |
| `total-max` | 出现「正文 ≤58 字」 | 硬 | 超长不拦 |
| `unique-icon` | 出现「全篇不重复」 | 软 | 三行同图标，且 `dedupeIcons` 不启用 |
| `fact-source` / `fact-band` | 出现「事实结论」 | 硬 | 编造的现象词、时段全部放行 |
| `tightUnits` | 同时出现「紧贴」和「°C」 | — | `-1.4 °C` 与 `-1.4°C` 两版随机 |
| `line-max` | 「每行 ≤N 字」 | 硬 | 天气任务不用它，别误加 |

## 7 改动入口

- 全局默认：`PUT /api/settings`，body 只带 `{"ai":{"defaultPrompt":"…"}}`；服务端对掩码 `apiKey` 有保留逻辑，其余 ai 字段由 `deepMerge` 继承
- 任务提示词：`POST /api/tasks/upsert`，`items` 里放**完整 task**（只带 `config.notifyPrompt` 会丢 url/steps）
- 写完必查：`\uFFFD` 为 0、长度与源文件一致、`steps` 与 `retry` 未变
- 不产生通知的验证：`POST /api/ai/preview`（回 system/user/rules，不调模型）
