# 提示词全景

> 读者是模型，不是人：每条要么指向一个字段，要么指向一个输出位置；不写理由，不写版本戳。
> 对应代码：`server.js` 的 `aiPrompts()` / `aiRules()` / `aiReview()` / `orderBandAfterDay()`。
> 最近整理：2026-11-15 第二十九批（`build=audit-batch-30`）。

## 写入原则（这一轮定的）

1. **声明式**：写「现象←本行「现象=」」「缺最高 → 只写最低」，不写「宁可缺一项，不可编一项」这类修辞——模型不缺态度，缺的是字段映射。
2. **先给形态，再给规则**：模板放在引用它的规则之前。「第 3 行＝…」写在模板之前会悬空，实测直接丢掉预警与降水时段。
3. **能查表就别写散文**：建议句与图标合成一张 `条件 → 图标+短句` 的对照表，模型不用做两次独立决策。
4. **能数就别形容**：`3 行`、`5 个字段`、`58 字`、`<=160 字`，都不留给模型自己判断。
5. **元信息不进提示词**：版本号、编辑时间放本文件；提示词里每一字都要约束输出。
6. **机检触发词是字面量**：删掉那句话＝关掉那条校验，见第 5 节。

## 拼装顺序

```
system = 内置骨架（669 字）+ 【本任务要求】（任务 config.notifyPrompt，可空）
user   = 任务 / 【原通知】或【材料】/【接口原始数据】/【默认优化要求】/【交付前自检】
```

优先级：**任务要求 > 体例 > 默认要求**；**事实、禁止 > 任务要求**。

`【原通知】` 与 `【材料】` 二选一：有 `rawData` 时原文只是「可参考、非事实来源」；没有 `rawData` 的长文本任务（热评）里，原文就是材料本身。混用会让模型把上一版通知当数据抄。

## 1 内置骨架（669 字，随代码走）

| 段落 | 管什么 | 下游机检 |
| --- | --- | --- |
| 角色与输出契约 | 只输出 `{"title","body"}`；body 内 `\n` 分行 | 解析失败即重试 |
| 事实｜不可违反 | 数字/时刻/名称逐字可查；带原单位；多口径不合并；缺项不占位 | `fact-number` |
| 按材料形态选写法 | 结构化数据只留 3~6 项；长文本提炼 2~4 点 | — |
| 禁止 | 放之皆准的空话、泛建议、字段名入正文、自称 | `no-filler` |
| 体例｜**默认值：任务要求可逐条覆盖** | ≤160 字、首行给结论、中文标点、数字与单位留空格 | `no-markdown` `no-blank-line` |

`体例` 从「硬规定」降为「默认值」是这一轮的关键改动：天气任务要求 `°C` 紧贴数字，与骨架的「留空格」正面对撞，此前靠代码侧 `tightUnits` 硬掰；现在由提示词先声明覆盖关系，代码归一只是兜底。

## 2 全局默认提示词（25 字）

```
精简易读，突出关键数字；必要时给一句具体建议。
```

10 个没有自定义提示词的任务共用。**别写成含「每行 N 字」「只输出 N 行」的句子**——那会给所有任务凭空加一条机检。

## 3 天气任务提示词（1034 字）

任务 `task_2c265324420b`「天气预报·三甲集」，正本 `docs/notifyPrompt-weather.txt`。

```
角色＝天气播报改写器。地点：甘肃临夏州广河县三甲集镇。今天 {{日期}}。
任务＝把「【事实结论】」的字段填进固定模板，不改写、不推算。

【数据源｜唯一】只取这 5 个字段，名称与结论区一致：
现象←本行「现象=」 最低←本行「最低=」 最高←明天行「最高=」 降水←本行「降水=」 预警←「预警名=」
取数范围仅「【事实结论】」区；逐日/逐小时原始行、状态串、【原通知】＝非数据，只供核对。
字段缺失 → 删该字段，不换口径、不写「暂无」。

【模板｜〈〉是占位符：不照抄，不当事实】
❄️ 今晚〈降水〉〈现象〉，最低〈最低〉°C
⛅ 明天〈降水〉〈现象〉，〈最低〉~〈最高〉°C
〈第 3 行＝预警行；「预警名=」为「无」时＝建议行〉
· 信息点用「，」；「今晚」「明天」写全，不缩写、不被时段挤到后面。
· 缺最高 → 只写〈最低〉°C；缺最低 → 温度整段删。
· 正文 ≤58 字；超限按序删：建议短句 > 明天温度区间 > 今晚最低。现象、降水、预警不删。
· 只输出 3 行，行末不加句号。

【降水】把本行「降水=」原值整段插进〈降水〉，效果＝今晚19-07时小雪。
时段是现象的定语：禁写成「今晚小雪，19-07时」，禁与温度换位。
24 小时制，末尾一个「时」；禁写成「19时起，7时停」「19时到7时」「19时-7时」「19-07」。
两行独立：一行有值不得省另一行，两行不得互换。正文每个「N时」必须在结论区降水区间内。

【预警｜占第 3 行】⚠️ 〈预警名〉；明早慢行
预警名逐字照抄，不加级别词、不减字；⚠️ 全篇只出现一次。「预警名=」为「无」→ 改走【建议】。

【建议｜仅无预警时占第 3 行】按第一个命中的条件取，图标与短句成对：
结冰/降雪/低温 → 🧣 明早慢行　降雨 → ☔ 带伞　沙尘/雾霾 → 😷 戴口罩
其余 → 💡 一句具体建议；晴热改用 🧢 防晒

【图标】今晚行/明天行按现象选，全篇不重复：
晴☀️ 多云⛅ 阴☁️ 雨🌧️ 雨夹雪｜雪❄️ 雾🌫️ 雷⛈️ 沙尘🌪️ 风≥5🌬️ 夜间晴🌙
表内天气词是选图标识，不是本次事实。

【单位】°C 紧贴数字，每个温度只带一个 °C；~ 两侧不留空格（覆盖「体例」的留空格默认）。

【降级】「【事实结论】」区为空或两行都取不到字段 → 只输出：
❄️ 数据不足
⛅ 本次不播报
💡 稍后重试

【裁决】禁止编造 > 数据源 > 模板 > 字数。
```

### 每段为什么这么写

| 段 | 作用 | 踩过的坑 |
| --- | --- | --- |
| 数据源 | 5 个字段的箭头映射，先掐死「从结论区取什么」 | 只写「只能取自结论区」时，模型会自己去逐小时行里找时段 |
| 模板 | 交付形态前置，后面的规则才有落脚点 | 模板排到规则之后 → 预警、时段双双丢失 |
| 降水 | 「时段是定语」＋反例，把时段钉在现象前 | 模型会把时段写成独立信息点：「今晚小雪，19-07时」 |
| 预警 | 固定占第 3 行，不按级别换行 | 按级别换行要挤第 4 行，实测会把预警整行丢掉；三行硬上限面前，固定位置才稳 |
| 建议 | 条件→图标+短句成对 | 分开选句与选图标时，出现「💡 明早慢行」这种错配 |
| 图标 | 只做选图，声明「表内天气词不是事实」 | 否则把「雨夹雪」当成本次现象写进正文 |
| 单位 | 显式声明覆盖体例 | 与骨架「留空格」冲突时输出会在 `-1.4°C` / `-1.4 °C` 之间摇 |
| 裁决 | 末行给优先级，利用末位权重 | 冲突没有裁决顺序时，模型随机选一条遵守 |

### 删掉的

`编辑时间` 版本戳、`禁 markdown / 空行`（骨架与机检已覆盖）、`行末不加句号` 的重复表述、按级别换预警行的分支、风级/紫外线/湿度阈值表。

## 5 机检规则触发词（改提示词别删这些字）

| 规则 | 触发条件 | 硬/软 | 删了会怎样 |
| --- | --- | --- | --- |
| `line-count` | 出现「只输出 3 行」 | 硬 | 少写一行照发 |
| `total-max` | 出现「正文 ≤58 字」 | 硬 | 超长不拦 |
| `unique-icon` | 出现「全篇不重复」 | 软 | 三行同图标，`dedupeIcons` 也不启用 |
| `fact-source` / `fact-band` | 出现「事实结论」 | 硬 | 编造的现象词、时段全部放行 |
| `tightUnits` | 同时出现「紧贴」与「°C」 | — | `°C`、`~` 的归一不执行 |
| `line-max` | 「每行 ≤N 字」 | 硬 | 天气任务不用它，别误加 |
| `emoji-per-line` | 「每行 1 个 emoji」 | 软 | 天气任务不用它，别误加 |

## 6 确定性归一（代码侧兜底）

模型即使 `temperature=0` 也会抖，凡是「改一下就能读通」的排版偏差都交给代码，不再多花一次调用：

| 函数/开关 | 处理 |
| --- | --- |
| `tightUnits` | `-1.4 °C` → `-1.4°C`；`-1.5 ~ 6°C` → `-1.5~6°C` |
| `dedupeIcons` | 重复图标按池顺序换成未用过的（`unique-icon` 才启用） |
| `orderBandAfterDay` | ①`19-07时今晚小雪` → `今晚19-07时小雪`；②`今晚小雪，19-07时` → 并回现象前；③`⚠️ …，明早慢行` → 分号 |
| `AI_POLISH_CACHE` | 按事实结论指纹缓存 30min，同材料同输出 |

## 8 改动入口

- 全局默认：`PUT /api/settings`，body 只带 `{"ai":{"defaultPrompt":"…"}}`；服务端对掩码 `apiKey` 有保留逻辑
- 任务提示词：`POST /api/tasks/upsert`，`items` 里放**完整 task**（只带 `config.notifyPrompt` 会丢 url/steps）
- 改完必查：`\uFFFD` 为 0、长度与源文件逐字一致、`steps` 与 `retry` 未变
- 不调模型的验证：`POST /api/ai/preview`（回 `system` / `user` / `rules`）
